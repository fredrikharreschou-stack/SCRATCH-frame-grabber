One change to your 1.4.2 code
-----------------------------
The gallery href was being built from the pattern segments:

    rel_parts = folders + [filename]
    out_path  = unique_path(os.path.join(out_dir, *rel_parts), self._used_paths)
    fname     = "/".join(rel_parts)

unique_path can rename the file -- it appends " 2" when two frames in one run
resolve to the same name -- and fname would still point at the un-renamed
path, leaving a broken image in the gallery. Now:

    fname = os.path.relpath(out_path, out_dir).replace(os.sep, "/")

Build folders
-------------
build-macos/   spec, icon generator and notes for the .app/.dmg. Used for
               every build so far, so it is known good.
build-windows/ the same for a Windows .exe, plus a ready-made ten-size
               icon.ico. WRITTEN ON macOS AND NOT TESTED ON WINDOWS -- it
               mirrors the macOS spec and should be treated as a starting
               point. Two things in it are worth reading whatever you use
               to package: customtkinter needs collect_data_files() or the
               app dies at launch on a missing theme, and icon.ico has to
               be bundled as a data file as well as passed to EXE(icon=),
               because the window icon is loaded at runtime through
               resource_path().

Structure
---------
_export_construct applies the export filters and hands rendering to
_render_pairs. The main pass and the unslated pass both go through
_render_pairs, so the two cannot drift apart in naming, numbering or resize
handling, and all three run modes share _export_construct and _finish_run.

Worth fixing at the source
--------------------------
`shot.audio.roll` is declared a float in Assimilate's OpenAPI spec but is
genuinely an alphanumeric sound-roll ID -- date-style rolls like "26Y08M22"
are normal from location sound recorders. The shim added in 1.4.0 stops it
killing a request, but the spec is where it belongs. Every tool built on that
SDK has the same landmine.

A diagnostic worth knowing
--------------------------
SCRATCH writes the stills itself, so a failed render comes back as
"409 Can not create file" even when the real cause is offline media. Check
the shot's .file path before hunting for a permissions or output-folder
problem.
